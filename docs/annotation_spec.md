# 标注规范说明

> 本文档定义人脸关键点标注的精确规范，包括关键点解剖学定义、边界框标准、标注流程和质量要求。

---

## 1. 坐标系定义

- **原点**：图片左上角 (0, 0)
- **X 轴**：向右为正
- **Y 轴**：向下为正
- **单位**：像素（整数）

```
(0,0) ────────────────────→ X+
  │
  │    ┌─────────────┐
  │    │  (x,y)      │
  │    │   ╔══════╗  │
  │    │   ║ FACE ║  │
  │    │   ╚══════╝  │
  │    │       (x+w, │
  │    │        y+h) │
  │    └─────────────┘
  ↓
  Y+
```

## 2. 关键点精确定义

> ⚠️ **视角约定**：所有"左/右"均采用**观察者视角**（看图人的左右），非被拍摄者自身的左右。

本项目使用 5 个简化关键点，从 MediaPipe 的 478 个稠密面部网格点提取而来。

### 2.1 left_eye — 左眼中心（观察者视角）

```
          观察者看图片时
          右侧的那只眼睛

          ● ← 左眼中心
```

- **解剖学位置**：左眼睑裂的几何中心（瞳孔在眼睑中的可视中心点）
- **提取方法**：取 MediaPipe 左眼区域 8 个关键点（索引 33, 133, 157, 158, 159, 160, 161, 246）的算术均值
- **精度要求**：误差不超过眼宽的 15%
- **遮挡处理**：若眼睛被遮挡但位置可推断，标注推断位置；若完全不可见，标记为 `[-1, -1]`

### 2.2 right_eye — 右眼中心（观察者视角）

```
     观察者看图片时
     左侧的那只眼睛

     ● ← 右眼中心
```

- **解剖学位置**：右眼睑裂的几何中心
- **提取方法**：取 MediaPipe 右眼区域 8 个关键点（索引 362, 263, 384, 385, 386, 387, 388, 466）的算术均值
- **精度要求**：同左眼
- **特别提醒**：确保不与被拍摄者自身的"右眼"混淆

### 2.3 nose_tip — 鼻尖

```
         ● ← 鼻尖
        / \
       /   \
```

- **解剖学位置**：鼻部最前突点，鼻中隔下端的正中点
- **提取方法**：直接从 MediaPipe 鼻尖关键点（索引 1）获取
- **精度要求**：误差不超过鼻翼宽度的 20%

### 2.4 left_mouth_corner — 左嘴角（观察者视角）

```
         观察者视角
         右侧嘴角

            ●
         ┌─┘ └─┐
         └─────┘
          ●
     左侧嘴角

     (观察者角度：右边→left, 左边→right)
```

- **解剖学位置**：左侧口裂的最外侧交汇点（嘴唇闭合线的最左端）
- **提取方法**：直接从 MediaPipe 左嘴角关键点（索引 61）获取
- **精度要求**：误差不超过嘴宽的 20%
- **注意**：区分"嘴角"与"嘴唇外缘"——嘴角是口裂的端点

### 2.5 right_mouth_corner — 右嘴角（观察者视角）

- **解剖学位置**：右侧口裂的最外侧交汇点
- **提取方法**：直接从 MediaPipe 右嘴角关键点（索引 291）获取
- **精度要求**：同左嘴角

## 3. 边界框（bbox）定义标准

### 3.1 定义

边界框是包围人脸区域的轴对齐矩形（axis-aligned bounding box），由四个整数参数定义：

| 参数 | 类型 | 说明 |
|------|------|------|
| `x` | int | 矩形左上角 X 坐标 |
| `y` | int | 矩形左上角 Y 坐标 |
| `width` | int | 矩形宽度（像素），必须 > 0 |
| `height` | int | 矩形高度（像素），必须 > 0 |

### 3.2 覆盖范围

边界框应覆盖：
- **上边界**：眉毛上沿（包含整个额头区域）
- **下边界**：下巴最下沿
- **左边界**：左耳/左脸颊最外侧
- **右边界**：右耳/右脸颊最外侧

### 3.3 数值约束

- 所有坐标值 ≥ 0
- width > 0, height > 0
- bbox 可以部分超出图片边界（会被自动 clamp）
- bbox 面积应占图片面积的 5%-80%（正常范围）

## 4. 标注 JSON 字段完整说明

### 4.1 必需字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `image_path` | string | 非空 | 图片相对路径（正斜杠） |
| `bbox` | object | 含 x/y/width/height | 人脸边界框 |
| `landmarks` | object | 含5个关键点 | 人脸关键点坐标 |
| `annotator` | string | 枚举值 | 标注者标识 |
| `date` | string | YYYY-MM-DD | 标注日期 |

### 4.2 可选字段

| 字段 | 类型 | 出现条件 | 说明 |
|------|------|----------|------|
| `confidence` | float (0-1) | auto/auto_partial | 人脸检测置信度 |
| `quality` | object | 质量评估启用时 | 图片质量评估详情 |
| `reviewer` | string | manual | 审核者标识 |
| `reviewed_from` | string | manual | 原始标注来源 |
| `modifications` | array | manual（有修改时） | 修改记录列表 |

### 4.3 annotator 枚举值

| 值 | 含义 | 触发条件 |
|-----|------|----------|
| `"auto"` | 自动标注成功 | 人脸检测 + 关键点提取均成功 |
| `"auto_partial"` | 自动标注部分成功 | 检测到人脸但关键点提取失败，关键点为 [-1,-1] |
| `"manual"` | 人工修正审核 | 经过交互式审核或批量批准 |

### 4.4 modifications 字段结构

每个人工修改记录包含：

```json
{
  "field": "bbox.x",           // 修改的字段路径
  "old": 574,                  // 修改前的值
  "new": 580                   // 修改后的值
}
```

字段路径使用点号分隔，如 `bbox.x`、`landmarks.left_eye`。

## 5. 标注流程

### 5.1 自动标注流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 加载图片  │ → │ 人脸检测  │ → │ 关键点提取 │ → │ 质量评估  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                     │
                    ┌──────────┐    ┌──────────┐     │
                    │ 保存JSON  │ ← │ 构建字典  │ ←───┘
                    └──────────┘    └──────────┘
```

**检测失败处理**：
- 无人脸 → 返回 None，不保存
- 有关键点提取失败 → 保存 partial 标注（annotator: "auto_partial"）
- 质量过低（auto_reject=True）→ 返回 None，不保存

### 5.2 人工审核流程

```
┌───────────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐
│ 加载自动标注 │ → │ 可视化预览 │ → │ 交互式修改 │ → │ 保存审核结果 │
└───────────┘    └──────────┘    └──────────┘    └───────────┘
                                       │
                                  ┌─────┴─────┐
                                  │ 可选操作:   │
                                  │ 1. 修改bbox │
                                  │ 2. 修改关键点│
                                  │ 3. 设置审核者│
                                  │ 4. 保存退出  │
                                  └─────────────┘
```

**审核操作**:
- `review` — 交互式逐字段修改
- `approve` — 信任自动结果直接通过
- `batch` — 批量批准所有待审核标注
- `compare` — 对比自动标注与人工修正的差异

## 6. 标注示例

### 6.1 正确标注示例

```json
{
  "image_path": "dataset/raw_images/温惠锦/001.jpg",
  "bbox": {
    "x": 150,
    "y": 200,
    "width": 500,
    "height": 520
  },
  "landmarks": {
    "left_eye": [300, 350],
    "right_eye": [500, 348],
    "nose_tip": [400, 460],
    "left_mouth_corner": [310, 540],
    "right_mouth_corner": [490, 538]
  },
  "annotator": "auto",
  "date": "2026-06-25",
  "confidence": 0.95
}
```

**检查点**：
- ✅ bbox 涵盖整个面部区域
- ✅ left_eye.x (300) < right_eye.x (500)（观察者视角左眼在右）
- ✅ eye_y (350) < nose_y (460) < mouth_y (540)（垂直层级正确）
- ✅ 嘴角 x 坐标与同侧眼睛大致对齐

### 6.2 Partial 标注示例（关键点提取失败）

```json
{
  "image_path": "dataset/raw_images/郭家兴/001.jpg",
  "bbox": {
    "x": 200,
    "y": 180,
    "width": 300,
    "height": 320
  },
  "landmarks": {
    "left_eye": [-1, -1],
    "right_eye": [-1, -1],
    "nose_tip": [-1, -1],
    "left_mouth_corner": [-1, -1],
    "right_mouth_corner": [-1, -1]
  },
  "annotator": "auto_partial",
  "date": "2026-06-25",
  "confidence": 0.72
}
```

> ⚠️ Partial 标注仅包含 bbox，需人工补充关键点信息。

### 6.3 人工修正后标注示例


## 7. 常见问题

### Q1：如何判断关键点位置是否正确？

检查以下约束：
1. **垂直层级**：eyes.y < nose.y < mouth.y（从图上方到下方）
2. **水平关系**：left_eye.x < right_eye.x, left_mouth.x < right_mouth.x（观察者视角）
3. **对称性**：左右眼 y 坐标差 < 眼宽的 20%，左右嘴角 y 坐标差 < 嘴宽的 20%
4. **关键点在 bbox 内**或 20% 容差范围内

### Q2：侧脸时关键点如何标注？

本项目主要处理正面脸，偏航角 ±30° 以内的侧脸可正常标注：
- 可见的关键点正常标注
- 被遮挡的关键点（如一侧嘴角不可见）标记为 `[-1, -1]`
- annotator 设为 `"auto_partial"`

### Q3：多人脸图片如何处理？

当前自动标注仅处理置信度最高的一张人脸。如需处理多人脸：
1. 使用 `FaceDetector.detect_all()` 获取所有人脸
2. 对每张人脸分别标注并裁剪
3. 或在采集阶段确保单张图片仅含一张人脸

### Q4：标注精度如何评估？

1. **结构校验**：`python -m src.validator`
2. **质量评估**：`python -m src.quality_report`
3. **人工抽检**：`python -m src.manual_reviewer review`

### Q5：标注文件可以手动编辑吗？

可以。标注文件是纯文本 JSON，可用任何编辑器修改。但建议修改后运行 `python -m src.validator` 校验合法性。
