# 数据采集规范

> 本文档规定人脸标注项目的数据采集流程、环境要求、设备标准和数据质量控制准则。

---

## 1. 数据来源

本项目的训练数据可通过以下渠道获取：

| 来源 | 方式 | 适用场景 | 注意事项 |
|------|------|----------|----------|
| **现场采集** | 摄像头拍照 / 手机拍照 | 定制化人脸识别系统 | 需获得被采集者的书面知情同意 |
| **Web 上传** | 浏览器拖拽或拍照上传 | 远程协作标注 | 使用项目自带的 FastAPI Web 界面 |
| **公开数据集** | 下载公开人脸数据集 | 模型预训练 / 基准测试 | 需遵循原数据集的使用许可协议 |
| **网络爬取** | 从公开网站收集 | 辅助数据补充 | 严格遵守 robots.txt 和相关法律法规 |

> ⚠️ **法律与伦理提醒**：采集和使用人脸数据须遵守《个人信息保护法》等相关法律法规。所有数据采集必须获得当事人的明确同意，不得采集未成年人的人脸数据（除非获得监护人同意）。不得将数据用于任何歧视性、监控性或侵犯隐私的目的。

## 2. 采集环境要求

### 2.1 光照条件

| 要求 | 标准 | 不良示例 |
|------|------|----------|
| 光照均匀 | 面部无明显阴影，左右脸亮度差 < 30 灰度值 | ❌ 单侧强光造成阴阳脸 |
| 避免逆光 | 人脸区域亮度 > 60（灰度值） | ❌ 窗口背光导致面部全黑 |
| 避免强侧光 | 面部高光区域 < 20% 总面积 | ❌ 日落侧光造成半脸过曝 |
| 色温中性 | 推荐 4500K-6500K（自然光/标准日光灯） | ❌ 纯黄色/蓝色灯光 |

### 2.2 背景

- **推荐**：纯色背景（白/灰/蓝）或简洁自然场景
- **避免**：复杂纹理（如密集树叶、条纹墙面）干扰人脸检测
- **避免**：背景中有其他人脸或类人脸图案（海报、雕塑等）

### 2.3 人脸占比

- **最低要求**：人脸区域（bbox）占图片面积 ≥ 15%
- **推荐范围**：20% - 50%
- **判断标准**：人脸 bbox 短边 ≥ 120 像素（基于 640×480 分辨率）

## 3. 设备与格式规范

### 3.1 分辨率

| 级别 | 分辨率 | 推荐用途 |
|------|--------|----------|
| **最低** | 640 × 480 (VGA) | 最小可用分辨率 |
| **推荐** | 1280 × 720 (720p) | 常规采集 |
| **理想** | 1920 × 1080 (1080p) | 高精度关键点标注 |

> 分辨率过低会导致关键点定位精度下降，建议不低于 640×480。

### 3.2 图片格式

| 格式 | 支持 | 推荐度 | 说明 |
|------|------|--------|------|
| JPEG (.jpg) | ✅ | ⭐⭐⭐ | 推荐，体积小，质量可调 |
| PNG (.png) | ✅ | ⭐⭐ | 无损压缩，文件较大 |
| BMP (.bmp) | ✅ | ⭐ | 无压缩，文件很大 |
| TIFF (.tif) | ✅ | ⭐ | 专业格式 |
| WebP (.webp) | ✅ | ⭐⭐ | 新一代格式 |

> 本工具支持 `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tiff`, `.tif`, `.webp` 七种格式。

### 3.3 画质要求

| 指标 | 标准 | 检测方法 |
|------|------|----------|
| **清晰度** | Laplacian 方差 ≥ 100 | QualityFilter.check_blur() |
| **亮度** | 灰度均值 40-220 | QualityFilter.check_brightness() |
| **对焦** | 人脸区域无肉眼可见模糊 | 人工目视 + 自动检测 |

## 4. 姿态与多样性要求

### 4.1 姿态范围

| 参数 | 允许范围 | 推荐范围 |
|------|----------|----------|
| **人脸倾斜角**（双眼与水平线夹角） | ≤ 30° | 0°（正面水平） |
| **偏航角**（左右转头） | ± 30° 以内 | 正面 |
| **俯仰角**（上下点头） | ± 20° 以内 | 正面 |

> 本项目的 MediaPipe 模型对正面和微侧脸效果最佳，大角度侧脸可能导致检测失败或关键点偏差。

### 4.2 多样性建议

为提高模型的泛化能力，建议在数据集中包含以下多样性：

- ☐ **表情变化**：自然/微笑/严肃各若干张
- ☐ **配饰变化**：戴眼镜/不戴眼镜（如适用）
- ☐ **发型变化**：刘海/露额头（如适用）
- ☐ **轻微光照变化**：不同时段/室内外交替
- ☐ **年龄跨度**（长期项目）：至少覆盖一个自然年度

### 4.3 每人推荐数量

- **基础**：≥ 10 张/人（覆盖基本表情和角度）
- **良好**：30-50 张/人（覆盖多种光照和场景）
- **充分**：≥ 100 张/人（覆盖全面多样性）

## 5. 命名与目录组织规范

### 5.1 目录结构

```
dataset/raw_images/
├── {人物姓名}/             # 按人物分文件夹
│   ├── 001.jpg             # 统一编号命名
│   ├── 002.jpg
│   └── ...
├── 温惠锦/
│   ├── IMG_0001.jpg
│   └── ...
└── ...
```

### 5.2 命名规则

- 文件夹名：使用人物姓名或唯一ID，避免空格和特殊字符
- 图片文件名：推荐 `序号.jpg` 或保留原始文件名
- 避免中文路径导致跨平台兼容问题（本工具已处理路径编码）

### 5.3 Web 上传

通过 Web 界面上传的图片自动以 UUID 命名，存储于 `web_app/uploads/`。可通过数据集整理工具（`dataset_organizer`）将 Web 上传图片自动归类到人物文件夹。

## 6. 质量检查清单

在将数据导入标注流程前，请逐项检查：

| # | 检查项 | 通过标准 | 不通过处理 |
|---|--------|----------|-----------|
| 1 | 图片可正常打开 | cv2.imread 返回非 None | 删除或重新导出 |
| 2 | 分辨率 ≥ 640×480 | 宽、高均满足 | 上采样或重新采集 |
| 3 | 人脸区域清晰 | Laplacian 方差 ≥ 100 | 重新拍摄 |
| 4 | 亮度适中 | 灰度均值 40-220 | 调整光照或后期处理 |
| 5 | 人脸倾斜 ≤ 30° | 双眼连线与水平夹角 | 旋转矫正或重新拍摄 |
| 6 | 人脸占比 ≥ 15% | bbox 面积 / 图片面积 | 靠近拍摄或裁剪 |
| 7 | 单张图片单人脸 | detect_all 返回 ≤ 1 个 | 裁剪或标记为多人脸图片 |
| 8 | 无遮挡 | 眼睛、鼻子、嘴巴均可见 | 重新拍摄 |
| 9 | 格式受支持 | 扩展名在 SUPPORTED_IMAGE_EXTENSIONS | 转换为 JPEG/PNG |
| 10 | 文件命名规范 | 无特殊字符、非空 | 重命名 |

## 7. 数据管理

### 7.1 版本管理

推荐使用 Git 或 DVC（Data Version Control）对标注数据进行版本管理：

```bash
# Git LFS 管理大文件
git lfs track "dataset/raw_images/**/*.jpg"
git lfs track "output/persons/**/*.npy"

# 或使用 DVC
dvc init
dvc add dataset/raw_images/
```

### 7.2 备份策略

- 原始图片：至少一份本地备份 + 一份异地/云端备份
- 标注 JSON：推荐使用 Git 进行版本控制
- 人物库 .npy：随标注 JSON 一并备份

---

## 8. 隐私与伦理

1. **知情同意**：采集前须告知被采集者数据用途、存储期限和删除权利
2. **数据最小化**：仅采集完成项目目标所需的最少数据
3. **去标识化**：在分享或发布数据集前，移除可直接识别个人身份的信息
4. **安全存储**：数据应存储在加密磁盘或受访问控制的服务器上
5. **删除权**：应被采集者要求，及时删除其所有相关数据
